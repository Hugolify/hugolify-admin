{{/* CurlyApostrophes ================ Turns the straight apostrophes inside words into typographic ones (`’`), in generated config text that is about to be parsed. Problem ------- Templates print text inside single quotes (`hint: '{{ . }}'`), so a straight apostrophe coming from an i18n string, ours or a site override, ends the string early: hint: 'Valeur de l'attribut rel du lien', → ',' or '}' must be specified Fix --- A quote that opens or closes a string always has a space, a bracket, a comma or a colon on one side, never a letter or a digit on both. So any `'` between two of them is text, whatever the format (YAML flow, JS object), and can safely become `’`, the spelling the i18n files already use. The replacement runs twice: matches cannot overlap, so a single pass leaves every other apostrophe of `rock'n'roll`. Date formats ------------ An uppercase letter between two quotes inside a word is the literal of a date format (`yyyy-MM-dd'T'HH:mm:ssX`, date-fns for Pages CMS), not two apostrophes: it is set aside first. Curled, the quotes no longer escape the `T`, which date-fns then reads as the timestamp in milliseconds. Usage ----- Call it wherever generated text is parsed or printed as code: {{- $text = partial "admin/func/CurlyApostrophes.html" $text -}} Input : string — raw YAML-like or JS-like content Output : string — the same content with apostrophes inside words curled */}} {{- $apostrophe := `([\pL\pN])'([\pL\pN])` -}} {{- $literal := `([\pL\pN])'(\p{Lu})'([\pL\pN])` -}} {{- $text := replaceRE $literal "${1}${2}${3}" . -}} {{- $text = replaceRE $apostrophe "${1}’${2}" $text -}} {{- $text = replaceRE $apostrophe "${1}’${2}" $text -}} {{- return replace $text "" "'" -}}
